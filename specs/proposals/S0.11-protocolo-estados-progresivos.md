# S0.11 · Protocolo de estados progresivos y canal en tiempo real

- **Tarea:** S0.11 · [tarjeta](https://trello.com/c/sprint0-s0-11)
- **Responsable:** FO
- **Brecha:** B4 (Estados por sondeo, no en tiempo real)
- **Estado:** acordada

## Problema

Actualmente, el frontend sondea repetitivamente endpoints REST mediante `window.setInterval` cada 2-3 segundos (`DossierJobsProvider.tsx:285` y `NotificationsProvider.tsx:177`).
No existe en backend ningún endpoint de streaming (`text/event-stream`), lo que genera peticiones innecesarias a la base de datos, introduce demoras de percepción de hasta 3 segundos en la interfaz y no permite ver el progreso individual de los agentes mientras se recopila información.

## Alcance

**Incluye:**
- Especificación del contrato de eventos Server-Sent Events (SSE).
- Definición de los tipos de eventos emitidos: `job_status`, `agent_progress`, `partial_result`, `heartbeat`, `job_completed`, `job_failed`.
- Política de reconexión con cabecera `Last-Event-ID` y retroceso exponencial.
- Soporte para autenticación JWT Bearer en el streaming.

**No incluye:**
- Implementación de WebSockets bidireccionales (descartada en ADR 0006).

## Diseño del Contrato de Eventos (SSE)

### Endpoint
`GET /dossiers/{id}/stream`
- **Cabeceras solicitadas:**
  - `Accept: text/event-stream`
  - `Authorization: Bearer <token_jwt>`
  - `Last-Event-ID: <id_opcional_para_resincronizacion>`

### Formato de los Mensajes SSE
Cada frame cumple la especificación estándar W3C SSE:
```
id: <uuid_o_secuencia>
event: <tipo_evento>
data: <payload_json>

```

### Tipos de Eventos y Payloads

1. **`agent_progress`:**
```json
{
  "dossier_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
  "agent_name": "agent_corporate_eu",
  "status": "running", // "started" | "running" | "completed" | "failed" | "skipped"
  "timestamp": "2026-09-09T18:30:00Z",
  "details": "Consultando registro corporativo de Francia (INPI / data.gouv.fr)..."
}
```

2. **`partial_result`:**
```json
{
  "dossier_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
  "section": "corporate_records",
  "data": {
    "jurisdiction": "FR",
    "company_name": "Alloxentric SAS",
    "status": "active"
  }
}
```

3. **`job_completed`:**
```json
{
  "dossier_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
  "status": "complete",
  "completed_at": "2026-09-09T18:30:18Z",
  "agents_summary": {
    "activated": ["uk", "us", "eu", "news"],
    "failed": []
  }
}
```

## Criterios de aceptación

- [ ] **CA1** — Dado un dossier en generación, cuando el cliente se conecta a `/dossiers/{id}/stream`, recibe inmediatamente un evento `job_status` con el estado actual.
- [ ] **CA2** — A medida que los agentes en LangGraph avanzan, el cliente recibe eventos `agent_progress` con el estado individual de cada agente en menos de 500 ms desde su cambio.
- [ ] **CA3** — Dado un corte transitorio de conexión, cuando el cliente reconecta enviando `Last-Event-ID`, el servidor reanuda la emisión sin duplicar eventos ya consumidos.
- [ ] **CA4** — Si transcurren 15 segundos sin actividad, el servidor emite un comentario `: ping` (heartbeat) para evitar el timeout del proxy en Render.

## Pruebas exigidas

| Categoría | Obligatoria | Qué cubre |
|---|:---:|---|
| Unitaria | ✅ | Serializador de eventos SSE y generador asíncrono. |
| Integración | ✅ | Consumo del stream con `httpx.AsyncClient` simulando eventos de cola. |
| Estrés | ✅ | Múltiples clientes SSE concurrentes consumiendo el canal de su organización. |
| Seguridad | ✅ | Rechazo 401 si no hay token Bearer o 403 si el dossier pertenece a otra organización. |
