# S0.9 · Esquema JSON estricto del dossier ejecutivo

- **Tarea:** S0.9 · [tarjeta](https://trello.com/c/sprint0-s0-9)
- **Responsable:** FO
- **Brecha:** B1 (Síntesis en Markdown sin contrato JSON validado)
- **Estado:** acordada

## Problema

Actualmente, `person_research_pipeline.py:190` persiste en la base de datos PostgreSQL (`models.py:319`, columna `dossier_data` de tipo `JSONB`) una estructura genérica no validada: `{"format": "markdown", "body": "..."}`.
No existe ningún modelo Pydantic en backend que valide la integridad de las secciones ni el tipo de datos generado por el LLM. En el frontend, la interfaz depende enteramente del parser `react-markdown`.
Consecuencias:
- Faltan entidades estructuradas para alertas de riesgo, trayectoria profesional contrastada, menciones de prensa y rompehielos de conversación.
- No hay trazabilidad de fuente por afirmación (objetivo OE5).
- Los fallos de formato del LLM se propagan directamente al usuario sin validación previa.

## Alcance

**Incluye:**
- Definición de esquemas Pydantic completos (`DossierOutput`, `ExecutiveSummary`, `PersonProfile`, `CompanyProfile`, `RiskAlert`, `ConversationStarter`, `PressMention`, `CorporateRegistryRecord`, `SourceCitation`).
- Soporte para trazabilidad estricta por afirmación (URL de origen, nombre del proveedor, fecha de consulta UTC).
- Esquema de metadatos de ejecución (agentes ejecutados, agentes fallidos, duración, métricas de tokens).
- Compatibilidad hacia atrás con el envoltorio histórico `{"format": "markdown"}` mediante un discriminator o modelo polimórfico en lectura.

**No incluye:**
- La modificación de las tablas de PostgreSQL (eso se aborda en S0.10 y S4.5).
- El ajuste del prompt de síntesis (se aborda en S4.2).

## Diseño de Datos (Modelos Pydantic)

```python
from enum import Enum
from typing import List, Optional, Dict, Any
from pydantic import BaseModel, Field, HttpUrl
from datetime import datetime

class SourceType(str, Enum):
    COMPANIES_HOUSE = "companies_house"
    SEC_EDGAR = "sec_edgar"
    EU_REGISTRY = "eu_registry"
    PEOPLE_DATA_LABS = "pdl"
    GDELT_NEWS = "gdelt_news"
    NEWS_API = "news_api"
    CALENDAR = "calendar"

class SourceCitation(BaseModel):
    source_type: SourceType
    source_name: str = Field(..., description="Nombre del proveedor o registro oficial")
    url: Optional[str] = Field(None, description="URL pública verificable del dato")
    retrieved_at: datetime = Field(..., description="Marca temporal UTC de la consulta")
    record_id: Optional[str] = Field(None, description="ID o número de registro (ej: Company Number o CIK)")

class RiskSeverity(str, Enum):
    LOW = "low"
    MEDIUM = "medium"
    HIGH = "high"

class RiskAlert(BaseModel):
    title: str
    severity: RiskSeverity
    description: str
    sources: List[SourceCitation]

class ConversationStarter(BaseModel):
    topic: str
    rationale: str
    suggested_opener: str

class CareerPosition(BaseModel):
    role_title: str
    company_name: str
    start_date: Optional[str] = None
    end_date: Optional[str] = None
    is_current: bool = False
    source: Optional[SourceCitation] = None

class PressMention(BaseModel):
    headline: str
    publisher: str
    published_date: Optional[str] = None
    summary: str
    url: str
    source: SourceCitation

class CorporateRegistryRecord(BaseModel):
    jurisdiction: str  # "UK", "US", "FR", "DE"
    company_name: str
    registration_number: str
    status: str  # "active", "dissolved", etc.
    incorporation_date: Optional[str] = None
    registered_address: Optional[str] = None
    officers: List[Dict[str, Any]] = Field(default_factory=list)
    filings_summary: Optional[str] = None
    source: SourceCitation

class DossierExecutivePayload(BaseModel):
    schema_version: str = Field("2.0.0", regex=r"^\d+\.\d+\.\d+$")
    meeting_context: Dict[str, Any]
    executive_summary: str = Field(..., min_length=20)
    participants: List[Dict[str, Any]]
    corporate_records: List[CorporateRegistryRecord] = Field(default_factory=list)
    career_trajectory: List[CareerPosition] = Field(default_factory=list)
    press_mentions: List[PressMention] = Field(default_factory=list)
    risk_alerts: List[RiskAlert] = Field(default_factory=list)
    conversation_starters: List[ConversationStarter] = Field(..., max_items=3)
    data_sources_used: List[SourceCitation]
```

## Criterios de aceptación

- [ ] **CA1** — Dado un JSON con la estructura completa de `DossierExecutivePayload`, cuando es validado por Pydantic, entonces instancia el objeto correctamente sin errores de validación.
- [ ] **CA2** — Dado un payload generado por el LLM que omite campos requeridos (ej: `executive_summary` o `conversation_starters`), cuando se intenta validar, entonces Pydantic lanza `ValidationError` con detalle exacto del campo faltante.
- [ ] **CA3** — Dado un registro corporativo o mención de prensa sin `source`, cuando se valida, entonces falla la validación exigiendo la cita de origen obligatoria (trazabilidad OE5).
- [ ] **CA4** — Dado un dossier histórico en formato `{"format": "markdown", "body": "..."}`, cuando el parser de lectura lo procesa, entonces es normalizado sin error a un objeto contenedor compatible.
